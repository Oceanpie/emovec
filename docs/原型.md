## 情感分析系统设计：零样本基线（Phase 0）

> **版本**：4.0
> **更新日期**：2026-04-18
> **定位**：三阶段演进路线的起点（Phase 0），已完成的零样本基线
> **后续阶段**：见 `模型训练.md`

---

### 1. 目的

将任意中文文本映射为 **8 维情感强度向量**，为下游任务提供结构化情感特征。

本阶段采用**原型库 + 相似度匹配**方案，无需训练数据即可运行，作为系统的零样本基线。Phase 0 已完成全部实现并通过 Pilot 验证（63 条测试样本，全部语义合理）。后续方向可能不再需要 MLP 训练，而是将原型库封装为轻量推理服务。

---

### 2. 情感分类方案

#### 2.1 八大情感类别

采用基于 **Plutchik 心理进化理论（1980）** 的 8 基本情感框架，这是情感科学中广泛引用的分类体系，具有 40+ 年的学术基础。

| 编号 | 英文 | 中文 | Plutchik 对极 |
|------|------|------|--------------|
| 1 | Joy | 高兴 | ↔ Sadness |
| 2 | Anger | 生气 | ↔ Fear |
| 3 | Sadness | 悲伤 | ↔ Joy |
| 4 | Fear | 害怕 | ↔ Anger |
| 5 | Disgust | 厌恶 | ↔ Trust |
| 6 | Surprise | 惊讶 | ↔ Anticipation |
| 7 | Trust | 信任 | ↔ Disgust |
| 8 | Anticipation | 期待 | ↔ Surprise |

> **设计说明**：  
> - Plutchik 的对极关系提供了天然的语义约束——同一文本不太可能同时在对极情感上获得高分。
> - "信任"和"期待"替换了原方案中的"忧郁"和"平静"，避免了语义重叠（忧郁≈悲伤）和非情感维度（平静=情感缺失）的问题。
> - 如需保留"忧郁"或"平静"作为细分维度，可在 150→8 映射中作为二级标签保留，但不作为 8 维输出的独立维度。

#### 2.2 理论依据

- **Plutchik, R. (1980)**. *Emotion: A psychoevolutionary synthesis*. Harper & Row.
- **Plutchik, R. (2001)**. The nature of emotions. *American Scientist*, 89(4), 344-350.
- 8 个基本情感可组合产生次级情感（如 joy + trust = love），这与 150 细分情绪条目 → 8 大类的聚合逻辑天然兼容。

#### 2.3 双方案对比实验

为实现 Phase 0 基线，我们同时标注了两套 8 维方案，用于对比选择：

| 维度 | 方案 A：Plutchik 标准 8 维 | 方案 B：原始方案 8 维 |
|------|---------------------------|---------------------|
| 1 | joy（高兴） | 高兴 |
| 2 | anger（生气） | 愤怒 |
| 3 | sadness（悲伤） | 悲伤 |
| 4 | fear（害怕） | 害怕 |
| 5 | disgust（厌恶） | 厌恶 |
| 6 | surprise（惊讶） | 忧郁 |
| 7 | trust（信任） | 惊讶 |
| 8 | anticipation（期待） | 平静 |

**方案 A（Plutchik）**：理论完备，有对极关系约束（joy↔sadness 等），但 "trust" 和 "anticipation" 在中文语境中不太自然。

**方案 B（原始方案）**：包含"忧郁"和"平静"两个东亚文化中高频的情感维度，但缺少对极约束，且"忧郁"与"悲伤"边界模糊。

两份标注结果分别存储在：
- `output/labels/labels_plutchik.json` — Plutchik 8D，153 条有效标注
- `output/labels/labels_original.json` — 原始方案 8D，153 条有效标注

最终方案将在 Pilot 验证中根据下游表现选择。

### 3. 情绪原型来源

采用蒂芙尼·瓦特·史密斯所著《人类情绪之书》（*The Book of Human Emotions*）中的情绪条目作为原型来源。

- 原书收录约 **150 个独立情绪条目**，每个条目包含详细的英文描述。
- 这些条目覆盖基本情绪到文化特定情绪，语义丰富。
- 每个条目将被映射到 8 大类之一（见第 5 节映射表）。

### 4. 原型向量生成

#### 4.1 编码模型

使用 **Qwen3-Embedding-8B** 对文本进行编码，采用双 Provider fallback 架构。

| 参数 | 值 | 说明 |
|------|-----|------|
| 模型 | Qwen3-Embedding-8B | C-MTEB 中文分类 76.97 |
| Provider 1 | ModelScope Inference API | `https://api-inference.modelscope.cn/v1`，key: `MODELSCOPE_TOKEN` |
| Provider 2 | SiliconFlow API | `https://api.siliconflow.cn/v1`，key: `SILICONFLOWS_TOKEN` |
| Fallback 策略 | ModelScope → SiliconFlow | 在 400/429 错误时自动切换 |
| 模型 ID | `Qwen/Qwen3-Embedding-8B` | 两端统一模型路径 |
| 输出维度 | **4096**（完整存储） | MRL 支持查询时截断到 32-4096 任意维度 |
| 数据类型 | float32 | 4 字节/维度 |
| 指令语言 | 英文 | Qwen 官方建议 |
| 并发控制 | 5 并发 | 编码条目时 |

> **双 Provider 设计**：ModelScope 为首选 Provider，SiliconFlow 作为备用。当 ModelScope 返回 400 或 429 错误时，自动 fallback 到 SiliconFlow，确保编码任务的鲁棒性。两个 Provider 使用相同的模型和参数，输出向量完全兼容。

#### 4.2 指令策略

**使用单一固定指令**，不对不同任务维护多套原型库。

```
Instruct: Given a Chinese emotional utterance, retrieve the most relevant emotion description that matches the emotional state expressed
Query: {text}
```

> **格式说明**：
> - **Query 端**：加 `Instruct: {instruction}\nQuery:{query}` 前缀，引导模型关注情感匹配
> - **Entry 端**：直接使用原始描述文本，不加 instruction 前缀
> - **语言**：指令用英文（Qwen3 官方建议），查询以中文为主
>
> **实验验证**（`scripts/test_instruction_aware.js`）：
> - instruction-aware 确实生效（同一文本加/不加 instruction，cosine 差异 0.72）
> - 加入 instruction 后匹配度提升约 29%（与目标 entry 的相似度更高）
> - 语义区分正确（相关 entry 得分高于不相关 entry）

> **设计变更说明**：
> 1. 原方案设计了多指令二级索引（&lt;100 指令 × 150 原型 = 15,000 向量），已简化为单一指令
> 2. 指令从 `"Classify the emotion expressed in the given text"` 改为检索式 `"Given a Chinese emotional utterance, retrieve..."`，更贴合 embedding 模型的检索范式
> 3. Query 端以中文为主，目标是匹配"说出那句话时里面包含的情感"

#### 4.3 每类多原型

每个大类使用 **5-10 个多样化原型**，而非单一代表文本。原型来源包括：

1. **《人类情绪之书》条目**：属于该大类的细分情绪描述（如 "Anger" 类下的 abhiman、rage、indignation 等）
2. **补充描述**：为覆盖度不足的大类补充简要描述文本

> **设计变更说明**：  
> 原方案每个情绪条目仅使用一个英文描述作为原型。改为每大类 5-10 个原型的理由：
> - 单原型对描述质量敏感，鲁棒性差
> - 多原型取 Top-K 平均可缓解个别原型偏差
> - 5-10 个 × 8 类 = 40-80 个原型，存储和计算开销可忽略

#### 4.4 原型向量存储

向量以 numpy `.npy` 文件存储，元数据以 JSON 文件存储，两者配合使用。

**向量文件**：`output/embeddings/prototype_vectors.npy`
- 形状：`(153, 4096)`，float32
- 存储 153 条有效条目的完整 4096D 向量（不截断）
- 查询时通过 `--dim` 参数按需截断到任意 32-4096 维
- 总大小：153 × 4096 × 4 bytes ≈ **2.4 MB**

**元数据文件**：`output/embeddings/prototype_meta.json`
- 条目描述、索引映射
- 双方案 8D 软标签（引用 `output/labels/` 中的标注结果）

> **双方案标签**：每个条目有两套 8D 软标签（Plutchik 维度和原始方案维度），分别存储在 `output/labels/labels_plutchik.json` 和 `output/labels/labels_original.json`，元数据文件中通过 `label_plutchik` 和 `label_original` 键引用。

> **设计变更说明（v3→v4）**：
> - v3 使用 FAISS `IndexFlatIP` 存储 512D 截断向量，v4 改为 numpy `.npy` 存储完整 4096D 向量
> - FAISS 依赖已完全移除，相似度计算使用 numpy 矩阵乘法（L2 归一化后内积，数学上等价于余弦相似度）
> - 旧版 FAISS 索引存档在 `output/embeddings/_archive_faiss/`

> **设计变更说明（软映射 vs 硬分类）**：
> 
> 原方案将 154 个条目硬归入 8 大类。经评估发现 29 个文化根植性情绪（如 SAUDADE、HAN、AMAE）无法干净归入单一类别——它们的存在恰恰说明 Plutchik 的 8 类覆盖不了所有文化的情感体验。
> 
> **解决方案**：每个条目拥有一个 8 维软标签（概率分布），而非硬分类。
> - 单一情感条目（如 ANGER）→ 近似 one-hot：`anger: 0.95, others: ~0`
> - 混合情感条目（如 SAUDADE）→ 多维非零：`sadness: 0.5, anticipation: 0.35, joy: 0.1`
> - 标签由 LLM 自动生成（见 §5），人工审核子集

#### 5.6 聚合方式

查询时，计算查询向量与全部 153 个原型的余弦相似度，取 Top-K 个最相似原型，对其相似度做 softmax 归一化为权重，再加权求和它们的 8D 软标签：

```
1. 截断: query_vec = query_raw[:, :dim], proto_vecs = proto_raw[:, :dim]
2. L2 归一化: query_norm = query_vec / ||query_vec||, proto_norm = proto_vecs / ||proto_vecs||
3. 余弦相似度: sims = proto_norm @ query_norm  (矩阵乘法，结果 shape=(153,))
4. 取 Top-K (K=7): top_indices = argsort(sims)[::-1][:K]
5. Softmax: weight_i = exp(sim_i / τ) / Σ_{j=1..K} exp(sim_j / τ)
6. 加权求和: output[d] = Σ_{i=1..K} weight_i × label_i[d]
```

- **K=7**：平衡信号聚焦与鲁棒性。太小的 K 对噪声敏感，太大的 K 引入不相关原型
- **τ（温度）**：控制 softmax 锐度。默认 τ=0.5，使权重集中在最相似的 1-2 个原型上
- **output[d] ∈ [0, 1]**：由 softmax 归一化保证权重和为 1，标签值在 [0,1]，加权结果自然在 [0,1]

### 6. 查询流程

#### 6.1 完整流程

```
输入文本（中文）
       │
       ▼
[编码] Qwen3-Embedding-8B（双 Provider fallback）
        指令: "Given a Chinese emotional utterance, retrieve
               the most relevant emotion description that matches
               the emotional state expressed"
        格式: Instruct: {instruction}\nQuery:{query}
        输出: 4096 维向量（MRL 可截断到 dim 维，默认 512）
       │
       ▼
[截断 + L2 归一化]
        query_raw = embedding(query, dim=dim)     ← 已截断，未归一化
        query_vec = query_raw / ||query_raw||      ← L2 归一化
        proto_trunc = proto_4096[:, :dim]          ← 原型同步截断到同维度
        proto_norm = proto_trunc / ||proto_trunc|| ← L2 归一化
       │
       ▼
[余弦相似度 = 归一化向量内积]
        sims = proto_norm @ query_vec              ← numpy 矩阵乘法
        结果 shape=(153,)，每值 ∈ [-1, 1]
       │
       ▼
[Top-K 筛选] 取相似度最高的 K=7 个原型
        top_indices = argsort(sims)[::-1][:K]
       │
       ▼
[Softmax 温度归一化] 将 K 个相似度转为权重（和为 1）
        weight_i = exp(sim_i / τ) / Σ exp(sim_j / τ)
        τ = 0.5
       │
       ▼
[加权求和] 用权重对 K 个原型的 8D 软标签加权平均
        output[d] = Σ weight_i × label_i[d]
       │
       ▼
输出: 8 维情感强度向量，每维 ∈ [0, 1]
```

#### 6.2 实现代码结构

查询管线核心逻辑在 `src/matching.py` 中，CLI 入口在 `scripts/match.py`。

```python
def run_query(text, proto_vecs, row_to_entry, dims, label_key,
              *, top_k=7, tau=0.5, dim=512, instruction=..., verbose=False) -> QueryResult:
    # 1. Embed query with instruction prefix
    query_raw = get_embedding(text, instruction=instruction, dim=dim)
    # 2. L2 normalize query
    query_vec = query_raw / max(norm(query_raw), 1e-10)
    # 3. Truncate prototypes to same dim + L2 normalize
    proto_trunc = proto_vecs[:, :dim].copy()
    proto_normed = proto_trunc / max(norms, 1e-10)
    # 4. Cosine similarity = dot product of normalized vectors
    sims = proto_normed @ query_vec  # (153,)
    # 5. Top-K
    top_indices = argsort(sims)[::-1][:top_k]
    # 6. Softmax
    weights = softmax(sims[top_indices], tau)
    # 7. Weighted label sum
    output[d] = sum(weight_i * label_i[d])
    return QueryResult(text, scheme, dim, top_k, tau, scores, matches)
```

#### 6.3 参数选择

| 参数 | 默认值 | 说明 |
|------|--------|------|
| dim | 512 | 查询时截断维度，范围 32-4096，原型存储为完整 4096D |
| K | 7 | Top-K 原型数量。通过 Pilot 实验确认 |
| τ | 0.5 | Softmax 温度。τ↓ 更集中（只信最相似的），τ↑ 更均匀（多原型参与） |

#### 6.4 余弦相似度的已知限制与缓解

| 已知限制 | 缓解措施 | 效果 |
|---------|---------|------|
| **否定盲区**："不开心" ≈ "开心" | 期待后续阶段解决 | 基线阶段不解决，记录为已知缺陷 |
| **极性坍缩**："爱" ≈ "恨" | Plutchik 对极约束 + Top-K softmax 聚焦 | 部分缓解 |
| **强度擦除**："有点烦" ≈ "暴怒" | softmax 温度拉开权重差异 | 部分缓解 |
| **各向异性**：所有向量对相似度偏高 | 维度截断 + softmax 温度 | 显著缓解 |

### 7. Pilot 验证实验（已完成）

#### 7.1 实验设计

#### 7.2 结果

- **63/63 条结果语义合理**：经人工审核，全部 63 条测试文本的匹配结果在语义上均可接受
- Embedding 模型能准确捕捉文本中的隐含情绪，即使情感表达含蓄或依赖上下文
- 原型库匹配方案对长文本、对话体、文学性表达均有良好的适应性

- 两套标签方案（Plutchik vs 原始方案）在 Pilot 中表现相近，最终方案选择待定

### 8. 存储与部署

| 项目 | 规格 |
|------|------|
| 原型向量总数 | 153 个（每有效条目一个，1 条重定向跳过） |
| 存储维度 | 4096（完整存储，避免模型升级时重编码） |
| 查询维度 | 可选 32-4096（通过 `--dim` 参数，默认 512） |
| 向量存储格式 | numpy `.npy` 文件（153×4096，float32，约 2.4 MB） |
| 元数据存储格式 | JSON（条目信息 + 双方案 8D 软标签） |
| 8D 软标签 | 153 组，LLM 5 轮标注取均值 |
| 推理延迟 | 1 次 Embedding API 调用 + numpy 矩阵乘法 + Top-7 softmax（< 1ms 本地计算） |
| GPU 需求 | 仅编码时需要（Qwen3-Embedding-8B 约 15GB VRAM） |
| 外部依赖 | numpy（无 FAISS 或其他向量数据库依赖） |

**部署方向**：原型库体积小（~2.4 MB 向量 + ~200 KB 标签），计算简单（一次矩阵乘法），适合封装为轻量推理服务。后续方向是用编译型语言（如 Go/Rust）实现静态原型数据加载 + 余弦相似度计算，避免 Python 运行时开销。

### 9. 维护与版本控制

- **版本绑定**：原型库与 Qwen3-Embedding 模型版本绑定，升级模型需重编码所有原型（`scripts/build_prototype.py --force`）
- **映射表独立维护**：154→8 软标签可独立于向量更新（重新标注不影响向量）
- **增量构建**：`build_prototype.py` 支持增量模式，只编码新增/变更的条目
- **变更日志**：记录每次原型库更新的模型版本、日期、变更内容
