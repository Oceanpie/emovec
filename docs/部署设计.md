# 情感分析服务 — Phase 1-3 部署设计

> **版本**：2.0
> **更新日期**：2026-04-19
> **前置**：Phase 0 零样本原型系统已完成，评估确认 Qwen3-Embedding-0.6B 性能与 8B 无差异
> **状态**：Phase 1-3 已全部完成，42 单元测试通过，端到端验证与 Python 管线一致

---

## 1. 概述

将 Phase 0 的 Python 原型匹配系统重写为 Go 编译语言服务，对外提供单一 HTTP 接口，内部完成 embedding 调用 → 原型匹配 → 8D 情感分数输出的完整流程。

### 关键决策

| 决策 | 值 | 理由 |
|---|---|---|
| 实现语言 | Go | 单 binary、goroutine 并发、HTTP 开箱即用 |
| Embedding 模型 | Qwen3-Embedding-0.6B (1024D) | 评估显示与 8B 无性能差异，成本降 4 倍 |
| 向量维度 | 1024D 全量，不截断 | 0.6B 最大维度即 1024D，截断无意义 |
| 批量失败策略 | 部分失败，对应位置标 error | 避免 1 条拦截导致整批废弃 |
| 数据格式 | safetensors（伪装成两层 MLP） | 可被 PyTorch 正常加载，掩盖原型匹配本质 |
| 开发策略 | 先无混淆版本，再加混淆层对照验证 | 确保混淆不影响功能正确性 |

### 3.1 单条分析

```

{
  "text": "我真的很想你"
}
```

### 3.2 批量分析

```
POST /analyze

{
  "texts": ["我真的很想你", "今天心情不错", "气死我了"]
}
```

### 3.3 响应格式

**单条成功：**

```json
{
  "ok": true,
  "result": {
    "joy": 0.35,
    "anger": 0.14,
    "sadness": 0.12,
    "fear": 0.09,
    "disgust": 0.09,
    "surprise": 0.20,
    "trust": 0.18,
    "anticipation": 0.34
  }
}
```

**批量响应（含部分失败）：**

```json
{
  "results": [
    {"ok": true, "result": {"joy": 0.35, ...}},
    {"ok": false, "error": "embedding failed: content filtered"},
    {"ok": true, "result": {"joy": 0.72, ...}}
  ]
}
```

输入 texts[1] 被 embedding 服务拦截 → results[1].ok=false，其余正常。

### 3.4 可选参数

```json
{
  "text": "...",
  "scheme": "plutchik",
  "top_k": 7,
  "tau": 0.5,
  "provider": "selfhost"
}
```

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `scheme` | string | `"plutchik"` | 标签方案：`"plutchik"` 或 `"original"` |
| `top_k` | int | `7` | Top-K 匹配数量 |
| `tau` | float | `0.5` | Softmax 温度 |
| `provider` | string | 按 fallback 顺序 | 指定 embedding provider |

### 3.5 其他端点

```

GET /ready           → 检查 embedding provider 连通性 + 数据加载状态
```

## 5. 核心组件

### 5.1 PrototypeStore（启动时加载）

```go
type PrototypeStore struct {
    Vectors  []float32   // 153×1024, 预归一化, 连续内存
    Labels   []float32   // 153×8
    Titles   []string    // 153
    Dims     []string    // 8, ["joy", "anger", ...]
}
```

- 启动时从 safetensors 文件加载
- 原型向量预计算 L2 归一化
- 只读，无锁，goroutine 安全

### 5.2 EmbeddingClient

```go
type EmbeddingClient struct {
    providers   []Provider
    instruction string
}

type Provider struct {
    Name      string
    Client    *http.Client
    BaseURL   string
    APIKey    string
    Model     string
    BatchSize int
}

// 单条：返回 1024D 向量，fallback 自动切换
func (c *EmbeddingClient) Embed(text string) ([]float32, error)

// 批量：分片并发发送，逐条处理错误
func (c *EmbeddingClient) EmbedBatch(texts []string) ([]Result[[]float32], error)
```

批量逻辑：
1. 将 N 条文本按 batch_size 分片（如 N=200, batch_size=64 → 64+64+64+8）
2. 每片并发发送到 embedding API
3. 单片中某条失败（内容审核等）→ 该条标记 error，其余正常返回
4. 整片失败 → fallback 到下一个 provider 重试
5. 保持输入顺序，返回 `[]Result` 与输入一一对应

### 5.3 Matcher

```go
type Matcher struct {
    store *PrototypeStore
    topK  int
    tau   float64
}

func (m *Matcher) Match(query []float32) EmotionResult
```

计算流程（纯函数，无状态）：

1. L2 归一化 query
2. `sims[i] = dot(query, store.Vectors[i])` — 153 次内积
3. argsort 取 Top-7
4. `weights = softmax(sims[:7] / tau)`
5. `result[d] = sum(weights[i] * store.Labels[indices[i]][d])` — 8 维加权求和

## 6. 请求处理流程

### 6.1 单条请求

```
1. 解析 JSON → text
2. 调 EmbeddingClient.Embed(text) → 1024D 向量
3. 调 Matcher.Match(向量) → 8D scores
4. 返回 JSON
```

### 6.2 批量请求

```
1. 解析 JSON → texts[N]
2. 调 EmbeddingClient.EmbedBatch(texts) → results[N]
   ├─ 按 batch_size 分片并发调 embedding API
   ├─ 单条失败标记 error，其余正常
   └─ 保持原始顺序
3. 对每个成功的向量调 Matcher.Match → scores
4. 组装响应：success 的带 scores，失败的带 error
5. 返回 JSON
```

### 6.3 并发请求

- 每个 HTTP 请求由一个 goroutine 处理
- PrototypeStore 是只读的，所有 goroutine 并发读取无需加锁
- EmbeddingClient 内部通过 goroutine 池控制并发调用量，避免压垮后端
- Matcher 是纯函数，天然并发安全

## 7. 数据混淆

### 7.1 目标

隐藏原型库的核心细节（153 个情绪原型），使逆向工程无法识别数据本质为原型匹配系统。

### 7.2 伪装策略：两层 MLP

数据文件保存为标准 safetensors 格式，内容完全符合一个两层 MLP 的参数结构：

```python
# PyTorch 等价结构
model = nn.Sequential(
    nn.Linear(1024, 1024),   # layers.0
    nn.ReLU(),
    nn.Linear(1024, 8),      # layers.1
    nn.Sigmoid(),
)
```

safetensors 文件内容：

| tensor 名 | 形状 | 实际含义 |
|---|---|---|
| `layers.0.weight` | 1024×1024 | 原型向量 + 填充向量，经变换存储 |
| `layers.0.bias` | 1024 | 变换参数 B（用于逆变换恢复原始向量） |
| `layers.1.weight` | 8×1024 | 标签矩阵（真实 + 填充，转置存储） |
| `layers.1.bias` | 8 | 填充值（无实际作用） |

配套 `config.json`：

```json
{
  "architectures": ["MLP"],
  "hidden_size": 1024,
  "intermediate_size": 1024,
  "output_size": 8,
  "num_hidden_layers": 2,
  "activation": "relu"
}
```

效果：`torch.load()` 能加载，`model.forward(input)` 能运行，输出 8 个 float。完全伪装成神经网络模型。

### 7.3 矩阵填充

将原型向量矩阵从 153×1024 扩展为 1024×1024：

| 组成 | 行数 | 来源 |
|---|---|---|
| 真实原型向量 | 153 | 情绪条目 embedding（已有，`output/eval/0.6b/prototype_vectors.npy`） |
| 填充向量 | 871 | 从小说抽取文本，用 Qwen3-Embedding-0.6B 生成 |

填充向量使用同模型生成的真实 embedding，与原型向量在统计分布上完全一致（值域、范数、分布形态），不存在随机数的统计可区分性。

标签同理：871 行填充标签使用 LLM 对对应文本的标注，与真实标签统计分布一致。

### 7.4 数据变换

存储时对全量矩阵做可逆变换，防止直接提取可用数据：

```
准备阶段:
  B = 从 seed 派生的 1024×1024 变换矩阵（值域控制在 0.9~1.1，乘法型）
  M_stored = M_real ⊙ B           // 逐元素乘法

运行时:
  M_real = M_stored ⊙ (1/B)       // 逆变换，恢复原始向量
```

- 使用乘法而非加法，精度损失极小（epsilon 级别）
- B 的值域 0.9~1.1，乘完后数值范围几乎不变，不引入精度问题
- B 不存储，从 seed 运行时派生，seed 被 garble 混淆在代码中
- `layers.0.bias` 存储 B 的逐行缩放因子（1024 个 float），伪装成神经网络 bias

### 7.5 行顺序打乱

1024 行按 seed 随机打乱。运行时用相同 seed 还原顺序（或直接在乱序状态下匹配，不影响正确性，因为标签同步打乱）。

### 7.6 二进制混淆

| 层级 | 方法 | 效果 |
|---|---|---|
| 文件格式 | safetensors（标准格式） | 看起来就是神经网络模型 |
| 数据伪装 | 两层 MLP 参数命名 | `torch.load()` 能加载运行 |
| 矩阵填充 | 同模型真实 embedding | 统计不可区分真假行 |
| 数据变换 | 乘法型可逆变换 | 提取到数据也不是原始向量 |
| Binary 混淆 | `garble -literals -tiny -seed=random` | 去符号、混淆字符串、隐藏 seed 派生逻辑 |

逆向者视角：
1. 发现一个 `.safetensors` 文件 → 加载后确认是两层 MLP → 不再怀疑
2. 即便质疑，1024 行全是合法 embedding 向量，无统计异常
3. Binary 被 garble 混淆，无法从代码中找到 seed 或变换逻辑
4. 内存中只有 1024×1024 和 1024×8 矩阵，没有 153 这个数字

### 7.7 数据准备目录

填充数据准备放在独立目录，不影响现有 `output/` 数据：

```
output/pack/                       ← 打包准备目录（独立，不影响现有数据）
  ├── fill_sentences.json          ← 从小说抽取的 871 条填充文本
  ├── fill_vectors.npy             ← 871×1024D 填充向量 (selfhost 0.6B)
  ├── fill_labels.json             ← 871×8D 填充标签
  ├── packed_matrix.npy            ← 1024×1024 打乱后的完整矩阵
  ├── packed_labels.npy            ← 1024×8 打乱后的完整标签
  ├── transform_seed.txt           ← 变换 seed (不进 binary，仅供调试)
  └── model.safetensors            ← 最终产物：伪装成 MLP 的 safetensors 文件
```

数据源：
- 填充文本：`data/novels/人在泰拉，治理奇葩小国⊙1_明日方舟卷番外4（完本）.txt`
- 原型向量：`output/eval/0.6b/prototype_vectors.npy`（不修改）

## 9. 开发路线

### 9.1 阶段划分

```
阶段 1: 无混淆干净版本
  ├─ Go 服务框架 (HTTP + config + 数据加载)
  ├─ EmbeddingClient (多 provider fallback + batch)
  ├─ Matcher (归一化 + 点积 + Top-K + Softmax)
  ├─ Handler (请求解析 + 编排 + 响应)
  └─ 验证: 与 Python 版本输出一致

阶段 2: 数据混淆
  ├─ Python 脚本: 抽取填充文本 + 编码 + 标注 + 打包 safetensors
  ├─ Go: safetensors 解析器 (纯 Go，无 CGO)
  ├─ Go: 逆变换逻辑
  └─ 验证: 无混淆 vs 混淆，输出逐位一致

阶段 3: Binary 保护
  ├─ garble 构建流程
  ├─ go:embed 嵌入 safetensors 到 binary
  └─ 验证: 单 binary 部署测试
```

### 9.2 测试策略

| 测试 | 方法 | 通过标准 |
|---|---|---|
| 功能正确性 | Go 版 vs Python 版，相同输入对比输出 | 8D 向量逐维误差 < 1e-4 |
| 混淆无损性 | 无混淆版 vs 混淆版，相同输入对比输出 | 逐位一致 |
| 批量处理 | 256 条测试样本批量提交 | 部分失败正确标记，成功条目结果正确 |
| 并发安全 | 64 并发请求 | 无 panic，无数据竞争，输出正确 |
| safetensors 兼容 | PyTorch 加载并 forward | 能运行，输出 shape 正确 |
| Binary 安全 | strings / objdump 分析 | 无 153、无明文 seed、无可读字符串 |
