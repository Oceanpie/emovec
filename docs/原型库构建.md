# 构建情感分析原型库

本文档说明如何从零构建情绪原型库——即零样本情感匹配管线的核心数据。

> **注意**：本仓库仅包含算法与服务代码。按照本指南自行构建原型库，不包含任何预构建数据。

## 概述

系统使用**基于原型的最近邻匹配**将中文文本映射为 8D 情感向量：

1. 定义一组情绪原型（例如，从人类情绪分类体系中选取）
2. 通过 LLM 为每个原型标注 8 维情感强度向量
3. 将每个原型的描述文本编码为 Embedding 向量
4. 查询时编码输入文本，通过余弦相似度找到最近的原型
5. 加权聚合原型的 8D 标签 → 最终输出

## 分步流程

### 第一步：选择情绪概念来源

选取有清晰自然语言描述的情绪概念来源。

**推荐来源：**

| 来源 | 说明 |
|------|------|
| 《人类情绪之书》(The Book of Human Emotions) | 约 150 个跨文化情绪条目，每个带详细描述 |
| Plutchik 情绪轮 | 8 种基本 + 24 种次级情绪，理论体系完善 |
| 学术情绪分类体系 | 如 WordNet-Affect、EmoLex、NRC Emotion Lexicon |

**条目格式：**

每个情绪概念应为一个独立文档，包含：
- 唯一标题（如 "Saudade"、"Anger"、"Amae"）
- 解释该情绪体验的自然语言描述
- 可选：指向相关情绪的交叉引用

### 第二步：标注 8D 情感分数

每个原型条目需要一个软标签：一个 8 维向量，每维表示该维度情感的强度。

**标签方案（二选一）：**

**Plutchik 8D（有心理学对极约束）：**

| # | 维度 | 对极 |
|---|------|------|
| 1 | joy（高兴） | ↔ sadness |
| 2 | anger（愤怒） | ↔ fear |
| 3 | sadness（悲伤） | ↔ joy |
| 4 | fear（害怕） | ↔ anger |
| 5 | disgust（厌恶） | ↔ trust |
| 6 | surprise（惊讶） | ↔ anticipation |
| 7 | trust（信任） | ↔ disgust |
| 8 | anticipation（期待） | ↔ surprise |

**原始方案 8D（包含东亚文化相关维度）：**

| # | 维度 |
|---|------|
| 1 | 高兴 |
| 2 | 愤怒 |
| 3 | 悲伤 |
| 4 | 害怕 |
| 5 | 厌恶 |
| 6 | 忧郁 |
| 7 | 惊讶 |
| 8 | 平静 |

**标注策略 — LLM-as-Labeler：**

使用大语言模型（如 DeepSeek Chat、GPT-4）生成 8D 标签。每个维度需包含：核心定义、行为表现、边界区分、强度梯度。

提示词模板（以 Plutchik 方案示例）：

```
你是一位精通跨文化情感理论的心理学家。
为给定的情绪条目评定它在以下八个维度上的分量（0.00~1.00）。

维度定义：
- joy（高兴）：正向愉悦状态，微笑、分享、想靠近刺激源
- anger（愤怒）：对障碍/挫败的敌意反应
- sadness（悲伤）：低落的情绪状态，失落、退缩
- fear（恐惧）：对威胁的预期，战斗/逃跑反应
- disgust（厌恶）：反感、排斥
- surprise（惊讶）：吃惊、新奇反应
- trust（信任）：安全、信赖、开放
- anticipation（期待）：前瞻性的期望

评分规则：
1. 每个维度 0.00~1.00，精确到两位小数
2. 纯基础情感条目 → 该维度约 0.95
3. 混合情感/文化特定情感 → 多个维度非零
4. 大多数条目在大多数维度上应为 0
5. 只输出 JSON，不要解释

输出 schema：
{"joy": float, "anger": float, "sadness": float, "fear": float,
 "disgust": float, "surprise": float, "trust": float, "anticipation": float}
```

**质量保证措施：**

| 措施 | 实现方式 |
|------|---------|
| 多轮取均值 | 每条目独立标注 N 轮（如 5 轮），取逐维均值 |
| 高方差标记 | 标准差 > 0.15 的条目标记为"高方差"，建议人工审核 |
| 重定向跳过 | 自动跳过 `*see*: XXX` 格式的重定向条目 |
| 幂等性 | 支持增量标注，跳过已完成的条目 |
| 定期保存 | 每处理 5 条自动保存中间结果，防止中断丢失数据 |

### 第三步：编码为 Embedding 向量

使用 Embedding 模型将每个原型的描述文本转换为向量。

**推荐的 Embedding 模型：**

| 模型 | 维度 | 说明 |
|------|------|------|
| Qwen3-Embedding-8B | 4096（MRL 支持截断） | 中文表现优秀，C-MTEB 76.97 |
| Qwen3-Embedding-0.6B | 1024 | 轻量模型，评估显示本任务上与 8B 无差异 |
| text-embedding-3-large | 3072 | OpenAI，通用效果好 |

**指令策略：**

仅在**查询端**添加检索式指令，原型条目端不加前缀：

```
Instruction: "Given a Chinese emotional utterance, retrieve the most
relevant emotion description that matches the emotional state expressed"

格式: Instruct: {instruction}\nQuery:{query}
```

- **条目端**：直接使用原始描述文本，不加 instruction 前缀
- **查询端**：编码前加 instruction 前缀
- 指令引导 Embedding 模型关注情感匹配

**编码流程：**

```
对每个原型条目：
  1. 读取自然语言描述
  2. 调用 Embedding API（不加 instruction 前缀）
  3. 保存返回的向量

配置：
  - Provider fallback：主 → 备（如 ModelScope → SiliconFlow）
  - 并发数：5 并行请求
  - 存储：全部编码为 (条目数 × 维度) float32 数组
```

### 第四步：构建并验证原型库

**存储格式：**

| 项目 | 格式 | 形状 |
|------|------|------|
| 向量 | numpy .npy | (N_entries, D_dimensions), float32 |
| 标签 | JSON | N_entries × 8D 分数 |
| 元数据 | JSON | 模型信息、条目映射、维度信息 |

**验证检查：**

- 确认所有条目都有对应的向量和标签
- 检查向量中是否有 NaN/Inf
- 验证标签值在 [0, 1] 范围内
- 确认 Embedding 维度符合预期

### 第五步：实现匹配管线

核心算法（在 `src/matching.py` 和 `emovec/internal/matching/` 中实现）：

```
输入：查询文本
  1. 编码：embedding(text, instruction, dim=D) → query_raw
  2. 归一化：query_vec = query_raw / ||query_raw||
              proto_norm = proto_vectors / ||proto_vectors||
  3. 余弦相似度：sims = proto_norm @ query_vec     # 点积
  4. Top-K：top_indices = argsort(sims)[::-1][:K]
  5. Softmax：weights = softmax(sims[top_indices], tau)
  6. 加权求和：output[d] = sum(weights[i] × labels[i][d])
输出：8 维情感强度向量
```

**关键参数：**

| 参数 | 默认值 | 说明 |
|------|--------|------|
| dim | 512–1024 | Embedding 维度（MRL 截断） |
| K | 7 | 最近邻原型数量 |
| τ | 0.5 | Softmax 温度（越小聚焦越锐利） |

### 第六步：打包以供 Go 服务（可选）

Go 服务（`emovec/`）期望原型数据为 safetensors 格式：

| Tensor 名 | 形状 | 内容 |
|-----------|------|------|
| `layers.0.weight` | N×D | 原型向量 |
| `layers.1.weight` | 8×N | 原型 8D 标签（转置） |

可选的数据混淆策略：
- **矩阵填充**：使用无关文本的真实 Embedding 将 N×D 矩阵填充至 D×D
- **行打乱**：基于 seed 对行做置换打乱
- **乘法变换**：对矩阵做逐元素变换（K×B，B 从 seed 派生）
- **伪装**：打包数据使其看起来像两层 MLP 的权重文件

详见 [docs/部署设计.md](部署设计.md)。

## 完整管线参考

```bash
# 1. 从原始材料解析独立条目
#    从书籍或分类体系中提取情绪概念

# 2. 通过 LLM 生成 8D 标签
#    每条目用 Plutchik 或原始方案标注，5 轮取均值

# 3. 编码条目为 Embedding 向量
python scripts/build_prototype.py

# 4. 验证原型库
#    检查维度、验证标签、测试几条查询

# 5. 运行查询
python scripts/match.py "你的输入文本"
```

> 上述脚本是数据处理工具，不在本仓库中。请按本指南中的方法论自行实现等价逻辑。

## 注意事项

- 原型库与 **Embedding 模型版本绑定**，升级模型需重新编码所有原型
- 标签和向量相互独立：更新标签无需重新编码
- 153–200 个原型是比较合适的范围——覆盖足够广，匹配计算亚毫秒级完成
- 匹配计算开销可忽略（< 1ms），瓶颈永远是 Embedding API 调用
